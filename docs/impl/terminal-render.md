# Terminal render (temporary implementation doc)

Delete this file in the change that completes the work.

**Goal:** the `proschi` Claude Code plugin also draws Proschi diagrams natively
in Claude Code's terminal: the architecture as cell art, animated use-case
playback, simulation badges and copy/open buttons.

## Decisions

- Lives in the existing `plugin/` (hooks module next to the skills): one
  install gives skills and rendering.
- Cell art with the mod API's `Raster` (terminal only), not pixel images:
  native in every terminal. Other surfaces fall back to the engine's own drawing.
- Layout: the browser's ELK layout (`frontend/src/dsl/autoLayout.ts`
  `layoutGraph`), scaled to cells, so placement matches the browser.
  Claude Code refuses any hooks-module file over 1 MiB and ELK is 1.59 MB, so
  ELK runs in Node: `plugin/hooks/layout.cjs` (source/imports JSON on stdin,
  Layout JSON on stdout), spawned with `$.process.run`, cached per document.
  User chose this over a native layout; needs Node on PATH like the skills.
- Pure core in `tooling/src/terminal/` (testable with vitest); hooks source in
  `plugin/src/register.tsx`. `tooling/build.mjs` bundles both into
  `plugin/hooks/` (committed: the plugin installs from git). The hooks bundle
  is NOT minified: the engine statically reads it (`register` must be a
  function declaration, `$` never put in an object, state refs literal).
- Typecheck the hooks: `plugin/tsconfig.json` (needs the engine-laid
  `.claude-plugin/types`, gitignored), `claude plugin validate plugin`.
- Triggers: ```` ```proschi ```` fences in replies, Write/Edit rows of
  `*.proschi` files, `/proschi view <file>` pane.
- Cards look like the canvas's: heavy ink border plus a half-cell hard shadow
  (▌ right, ▀ below, only on empty cells so edges keep their lines).
- Icons: the canvas's icon per tech (generated by build.mjs from
  iconMapping.tsx into `tooling/src/terminal/techIcons.gen.ts`) as BMP Nerd
  Font glyphs, monochrome like the web; plugin setting `icons`
  (`nerd-font` default | `symbols` per kind | `none`). Braille-rasterised SVG
  icons were tried and are unreadable at card size.
- Use case panel (bordered, like the editor's player): scenario picker, step
  count, progress bar, step list (✓ done, ▶ current, window of 7), current
  step's request/response body, Restart/Back/Play/Next/End, colour legend.
- Playback copies the editor's player (UseCasePlayback.tsx): one step per call,
  pink packet out and back (red on an error, ✗ when cut), active nodes lit,
  the scenario's path faded less than the rest, TRAVEL 1500 ms / STEP 2000 ms,
  step panel with badges and bodies, ⏮ ‹ Play › ⏭ controls. Repaints in place
  with `$.ui.blit`.
- Diagram mode has a use case Select (grouped by endpoint) + Play + an explorer;
  play mode has ← Diagram, scenario tabs and Exit, like the editor.
- Icons can't be scaled in a cell: they sit in a 5×3 tile, as the canvas's tile.
- Copy buttons await `$.ui.copy` and toast the result; Open runs `open` /
  `xdg-open`, falling back to copying the link.
